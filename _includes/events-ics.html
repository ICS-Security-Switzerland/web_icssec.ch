{%- comment -%} The subscribable calendar: every event, in one language. include.lang 'en' | 'de' | 'fr' | 'it' Past events are included too. A subscriber's calendar should carry the association's history, and including everything keeps the file independent of the build date. The VCALENDAR wrapper and the individual events come from ics-head.html and ics-vevent.html, which the per-event download on each card uses as well. Known deviation: RFC 5545 section 3.1 says content lines longer than 75 octets should be folded, and these are not — the longest DESCRIPTION runs to roughly 300 characters. Liquid can only slice by character, not by octet, so a fold implemented here would not be octet-correct for the accented text this file carries anyway. The output was checked against a conforming parser (python icalendar) in all four languages. If a strict consumer ever turns up, this is the thing to fix. {%- endcomment -%} {%- assign by_date = site.data.events | sort: 'date' -%} {%- include ics-head.html lang=include.lang -%} {%- for ev in by_date -%} {%- include ics-vevent.html event=ev lang=include.lang -%} {%- endfor -%} END:VCALENDAR
